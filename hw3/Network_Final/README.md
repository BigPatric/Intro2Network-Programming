## 系統架構說明

本系統採用主從式架構（Client-Server），包含一個中央伺服器（Server）以及兩種不同的客戶端：開發者端（Developer Client）和玩家端（Lobby Client）。

### 1. Server (伺服器端)

伺服器採用了多執行緒、服務分層的設計，以清晰地劃分職責並提高可維護性。

- **`server_main.py`**: 伺服器主入口。 負責監聽網路連線，並為每一個連入的客戶端建立一個獨立的執行緒進行處理。
- **`connection_manager.py`**: **核心連線管理器**。這是一個單例物件，集中管理所有活躍的客戶端連線，追蹤哪個 `socket` 對應哪個使用者，並處理使用者上線與離線的狀態。
- **`developer_service.py`**: **開發者服務層**。處理所有來自開發者端的業務邏輯，例如開發者登入、註冊、上傳遊戲等。
- **`lobby_service.py`**: **大廳服務層**。處理所有來自玩家端的業務邏輯，例如玩家登入、註冊、獲取線上玩家列表、建立遊戲房間等。
- **`db_manager.py` / `db_initalize.py`**: 資料庫管理層。負責與 SQLite 資料庫進行所有互動，包含使用者驗證、遊戲資訊存取等。

### 2. Clients (客戶端)

開發者端和玩家端現在採用了統一的**長連線**架構，以提供更穩定和即時的互動體驗。

- **長連線機制**: 客戶端在啟動時即與伺服器建立一個 TCP Socket 連線，並在整個應用程式生命週期中保持該連線。所有後續操作（登入、註冊、請求資料等）都重複使用此連線。
- **登出功能**: 兩端都實現了完整的登出邏輯。當使用者登出時，客戶端會向伺服器發送 `logout` 指令，伺服器會更新 `ConnectionManager` 中的使用者狀態，然後客戶端返回登入介面。
- **GUI**: 使用 `tkinter` 建立圖形化使用者介面，透過多個 `Frame` 的切換來展示不同功能頁面（如登入、註冊、主功能頁）。

## 角色與客戶端詳解

### 「遊戲客戶端 (Game Client)」是什麼？

**遊戲客戶端**是指**實際可執行的遊戲程式本身**。它與**大廳客戶端 (Lobby Client)** (`lobby_gui.py`) 是**分開**的。

整個流程如下：

1. **大廳客戶端 (Lobby Client - "等候室")**: 玩家使用 `lobby_gui.py` 登入、查看可玩遊戲、加入或建立一個「房間」來準備玩特定的遊戲。它的主要工作是將玩家組織起來。
2. **伺服器 (Server - "媒合者")**: 當一個房間滿員且房主開始遊戲時，伺服器會向該房間內的所有玩家發送「開始遊戲」的指令。
3. **遊戲客戶端 (Game Client - "真正的遊戲")**: 在收到「開始遊戲」指令後，大廳客戶端的職責就是啟動實際的遊戲程式（也就是**遊戲客戶端**）。這個遊戲客戶端就是由開發者上傳的程式碼。它會連線到伺服器（或一個新的、專為該場遊戲開設的伺服器程序）來處理即時的遊戲邏輯，例如玩家移動、分數計算等。

**比喻：** **大廳客戶端**就像是 Steam 應用程式，你用它來瀏覽你的遊戲庫並邀請朋友組隊。當你點擊「開始遊戲」時，Steam 會啟動**遊戲客戶端**，也就是遊戲本身（例如《絕對武力》或《Dota 2》）。

### 職責劃分 (玩家 vs. 開發者)

#### 玩家 (使用 Lobby Client)

* **目的**: 玩遊戲並與其他玩家互動。
- **權限**:
  - 以玩家身份登入/註冊。
  - 瀏覽可用的遊戲列表（「遊戲商城」）。
  - 查看誰在線上。
  - 建立、加入和離開遊戲房間。
  - 啟動並遊玩實際的遊戲（透過遊戲客戶端）。
- **禁止**: 上傳、修改或刪除伺服器上的遊戲。

#### 開發者 (使用 Developer Client)

* **目的**: 在平台上建立和管理遊戲。
- **權限**:
  - 以開發者身份登入/註冊。
  - 上傳新遊戲到伺服器。
  - 用新版本更新現有遊戲。
  - (未來功能) 從伺服器刪除遊戲。
- **禁止**: 像普通玩家一樣加入遊戲房間或玩遊戲。他們的介面純粹用於內容管理。

## 關鍵架構改進

- **統一的長連線模型**: 先前 Developer Client 使用的短連線模型已被棄用。現在兩種客戶端都使用長連線，解決了因頻繁建立/關閉連線而導致的「註冊後無法立即登入」等狀態同步問題。
- **伺服器服務分層**: 伺服器邏輯被清晰地劃分為**連線層** (`server_main`)、**服務層** (`lobby_service`, `developer_service`) 和**資料層** (`db_manager`)，大幅提升了程式碼的可讀性和可擴展性。
- **中央化連線管理**: 透過 `ConnectionManager`，伺服器可以準確地追蹤所有線上使用者，為實現廣播、即時通知等功能打下了基礎。

## 各區塊與模組功能說明

- Developer Client (developer_gui.py)
提供開發者註冊、登入、上傳遊戲等功能的 GUI。
透過 TCP socket 與 Main Server 溝通。
- Lobby Client (lobby_gui.py)
提供玩家註冊、登入、遊戲房間、遊戲列表等功能的 GUI。
透過 TCP socket 與 Main Server 溝通。
- Main Server (server_main.py)
伺服器主程式，負責監聽所有 client 連線，並分派給對應服務。
多執行緒處理每個 client。
- ConnectionManager (connection_manager.py)
管理所有活躍連線，追蹤 socket 與使用者對應關係。
- DeveloperService (developer_service.py)
處理開發者相關業務邏輯（註冊、登入、上傳遊戲等）。
- LobbyService (lobby_service.py)
處理玩家相關業務邏輯（註冊、登入、房間、遊戲列表等）。
- DBManager (db_manager.py)
封裝所有資料庫操作。
不再直接操作 SQLite，而是透過 socket 與 DB Server 溝通。
- DB Server (db_server.py)
獨立進程，專責處理所有資料庫請求。
實際操作 SQLite，回應主伺服器的 CRUD 請求。
SQLite DB (users.db)
實際儲存所有使用者、遊戲等資料。
